# Predictive Maintenance for Water Pumps (Pump-Failure-Predictor)
**ATmega328P-based fault detection with 92% accuracy using TinyML (Edge Impulse)**

## Project Overview

This repository contains the firmware and supporting files for a predictive maintenance system designed to detect bearing failures in water pumps. It utilizes an ATmega328P microcontroller running bare-metal C code, leveraging TinyML via Edge Impulse for efficient, low-power fault classification based on vibration analysis. The system integrates with industrial environments using Modbus RTU and provides remote alerts via GSM SMS.

## Key Innovations & Features

### 🎯 **Ultra-Low Power ML on 8-bit MCU**
- **Edge Impulse TinyML Model:** Classification model (e.g., Decision Tree Ensemble) trained for bearing fault detection. (Target RAM usage ~1.2KB as per initial spec).
- **Fixed-Point FFT:** Optimized 256-point Fast Fourier Transform using Q8.24 fixed-point arithmetic (`firmware/main/fft_256.c`), minimizing RAM and computational overhead compared to floating-point on the ATmega328P.
- **Bare-metal C Firmware:** Optimized for performance and minimal footprint, avoiding framework overhead (`firmware/main/`).

### 🏭 **Industrial Integration & Communication**
- **Modbus RTU Slave:** Implemented using `avr-libc` for UART communication (`firmware/main/modbus_rtu.c`), enabling interoperability with PLCs and SCADA systems. Supports reading status/predictions (FC03) and potentially writing configuration (FC06).
- **GSM SMS Alerts:** Utilizes a SIM800L module (or similar) to send critical fault alerts via SMS (`firmware/main/gsm_alert.c`), providing remote notifications even in areas without consistent internet access. (Requires SoftwareSerial or careful UART management).

### ⚙️ **Hardware & Data Acquisition**
- **Vibration Sensing:** Samples an analog vibration sensor at 1kHz using the ATmega328P's ADC, triggered by Timer1 for precise timing (`firmware/main/sensor_reader.c`).
- **Hardware Design Files:** (Placeholders) Schematics and PCB layouts designed for robustness, potentially including considerations for EMI shielding (`hardware/`).

## Quick Start

1.  **Clone the repository:**
    ```bash
    git clone https://github.com/Gifted87/atmega-tinyml-pump-monitor.git
    cd atmega-tinyml-pump-monitor
    ```
2.  **Generate Edge Impulse Model:**
    *   Train your vibration classification model in [Edge Impulse Studio](https://studio.edgeimpulse.com/).
    *   Deploy the model as a **C++ Library**.
    *   Copy the generated source files (entire directory) into the `firmware/edge-impulse/` folder, replacing the placeholder files (`model.h`, `ei_classifier.c`, and the `edge-impulse-sdk/` subfolder).
3.  **Configure:**
    *   Update `GSM_TARGET_PHONE_NUMBER` in `firmware/main/gsm_alert.h`.
    *   Verify `MODBUS_DEVICE_ADDRESS` in `firmware/main/modbus_rtu.h`.
    *   Ensure `platformio.ini` matches your specific ATmega328P board (e.g., `board = uno` or `board = pro8MHzatmega328`).
    *   **Implement UART/SoftwareSerial for GSM:** The placeholder `gsm_alert.c` requires implementation for `gsm_uart_*` functions if using SoftwareSerial. Choose and integrate a suitable library or implement bit-banging.
4.  **Build and Upload:**
    *   Requires [PlatformIO Core](https://platformio.org/install/cli).
    ```bash
    # Build the firmware
    pio run

    # Upload to the ATmega328P (ensure board is connected)
    pio run -t upload
    ```
5.  **Monitor (Modbus):**
    *   Connect a Modbus RTU master (e.g., via USB-to-RS485 adapter) to the ATmega328P's UART pins used for Modbus.
    *   Use a Modbus monitoring tool or PlatformIO's serial monitor:
    ```bash
    # Monitor serial output (configure for Modbus baud rate)
    pio device monitor -b 19200 --raw
    ```
    *   Use a Modbus tool to read registers (e.g., read Holding Register 0x0000 for status on slave ID 1).
